# Reproducibility map

**Public-checkout status (6 September 2026):** source inspection, a dataset-free synthetic contract demo and aggregate checks are available locally without downloading participant data. Full reproduction of the primary supervised/deep result requires authorized datasets, participant-linked intermediate ledgers, frozen splits and model checkpoints that are not included. A passing software or aggregate check is not a rerun of the 1.646 BPM experiment.

## What can be checked

| Layer | Public material | Remaining requirement / boundary |
|---|---|---|
| Synthetic output-contract example | `examples/candidate_release_demo.py` | Hand-written values; no video inference or trained selector accuracy claim |
| Unit and integration tests | `tests/`, `requirements-dev.txt` | Install development dependencies; report the current run separately from historical QA |
| Current manuscript summary | `headline_metrics.csv`, `protocol_summary.json` under `reproducibility/` | Aggregate transcription, not participant-level predictions or full recomputation |
| Primary supervised analysis | T704/T730/T731/T753 and related entry points | Authorized candidate tables, linked splits, preprocessing provenance and model checkpoints; `experiments/` ledgers are not bundled |
| Historical V31/V32 audit | `reproducibility/v32_submission/` | A separate branch with different estimands; do not replace the current manuscript's primary set-attention result with causal-path or EMPD values |
| Browser/API fixture replay | Validation harness and fixture manifest | Authorized private video fixtures and configured services; not independent clinical validation |

The primary manuscript mechanism selects the highest-scoring candidate within each window. Optional correction routes and the historical V32 causal path are separate branches; their evidence must not be merged into a single unqualified headline.

## Dataset-free checks

From the repository root:

```bash
python examples/candidate_release_demo.py
python -m unittest discover -s tests -p test_package_checksums.py -v
python reproducibility/v32_submission/scripts/verify_package.py
# Full current suite, after installing requirements-dev.txt:
python -m pytest -q
```

The V31/V32 verifier uses a separate, exact-byte `SHA256SUMS.public-lf.txt` manifest for the LF-normalized Git checkout. The original `SHA256SUMS.txt` is retained unchanged as historical provenance. Seventeen frozen aggregate files had original CRLF hashes but were committed with LF line endings; the verifier checks this specifically and rejects content changes. See [checksum provenance](../reproducibility/v32_submission/CHECKSUM_PROVENANCE.md). No historical aggregate, training/inference script, contract or reported metric was modified by that repair.

## Analysis order

1. Generate route- and ROI-specific heart-rate candidates.
2. Preserve candidate provenance, quality, harmonic and agreement evidence.
3. Fit or apply the candidate selector using participant-disjoint partitions.
4. Evaluate all-output accuracy separately from release/review behavior.
5. Resample whole participants for cluster-aware uncertainty.
6. Treat subject-disjoint risk analysis as a separate, explicitly bounded experiment.
7. Report each dataset, protocol key and statistical unit separately.

## Fixed seeds and thresholds

- Model seeds: `704`, `1704`, `2704`.
- Split/bootstrap seeds: `2024`, `2025`, `2026`.
- Analytical error thresholds: `5`, `8`, `10`, `15` BPM.
- Reference heart rate and candidate absolute error are training/evaluation fields, never release-time inference features.

## Entry points

- `scripts/run_t467_ubfc_protocol_aligned_candidate_selector.py`: protocol-aligned primary candidate table.
- `scripts/run_t730_harmonic_aware_selector.py`: harmonic-aware selector.
- `scripts/run_t731_candidate_ranker_harmonic_rescue.py`: candidate-ranker rescue branch.
- `scripts/run_t732_t731_bootstrap_ablation.py`: selector ablation and bootstrap summaries.
- `scripts/run_t901_subject_cluster_bootstrap.py`: participant-equal endpoints and whole-participant resampling.
- `scripts/run_t902_subject_disjoint_risk_control.py`: calibration/test participant split and risk diagnostics.
- `scripts/run_t913_isolated_runtime_profile.py`: measured partial runtime path; deep predictions may be precomputed.

Several scripts consume intermediate CSV files generated by preceding entry points. They fail closed when inputs are missing rather than silently substituting values. The public repository deliberately excludes those large or participant-linked intermediates; aggregate manuscript values are preserved in `reproducibility/headline_metrics.csv`.

## Claim boundary

The repository supports inspection of the candidate-aware architecture, executed analysis logic and aggregate protocol outputs. It does not establish matched literature-level superiority, participant-level risk guarantees, external generalisation, fairness, clinical utility or end-to-end real-time readiness.
